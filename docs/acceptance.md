# Критерии приёмки MVP

Инструмент считается полезным, если он закрывает обычный механический сценарий и оставляет редкие исключения для небольшой ручной правки в Word. Локальные референсные документы используются только для закрытой проверки, не входят в исходники и не являются безусловным источником правил.

## Границы

- один запуск обрабатывает одну госпитализацию;
- исходники: DOCX, DOC и RTF; PDF игнорируются;
- исходные документы не изменяются;
- все вычисления выполняются локально;
- legacy DOC/RTF открываются служебным Word только с принудительно отключёнными
  макросами;
- результат — обычный редактируемый DOCX;
- отсутствие специалиста, который не участвовал, не является ошибкой;
- недобор занятий отражается фактическим количеством и не маскируется.

## Обязательный сквозной сценарий

1. Пользователь выбирает папку эпизода.
2. Программа конвертирует legacy DOC/RTF во временные DOCX и рекурсивно читает
   документы.
3. Программа показывает найденные сведения, источники и предупреждения.
4. Пользователь может исправить основные тексты, домены МКФ, шкалы и процедуры.
5. Для МДРК-1 выбираются первые валидные профильные данные не позже первого
   заседания; повторные точки и динамика не выводятся.
6. Для МДРК-2 по каждому домену и шкале выбираются первая и последняя отдельные
   точки не позже итогового заседания; промежуточные копии схлопываются.
   Если профильная первичка не даёт исходной точки, однозначно распознанный
   прежний МДРК-1 может заполнить только отсутствующий baseline МКФ/шкалы.
7. Программа создаёт редактируемый DOCX, который открывается в настольном Word.

## Проверяемые бизнес-правила

- клиническая дата внутри документа приоритетнее имени и `mtime`;
- строки из первички невролога с явно указанным другим профильным специалистом
  не попадают в итоговую таблицу; домены с пустым ответственным сохраняются;
- `Pf` объединяется в одну описательную строку независимо от роли источника;
- ключ домена включает код, описание/уточнение и владельца;
- одинаковый код с разными сторонами/конечностями остаётся разными доменами;
- в диагнозе, анамнезах и исследованиях МДРК-2 сохраняется первичный текст и
  добавляются только содержательные датированные дополнения; «без изменений»,
  «без дополнений» и «по ИПМР» не считаются содержанием;
- пропавшая временная точка остаётся пустой и получает предупреждение, а не `0`;
- динамика МКФ: меньший квалификатор — `+`, равный — пусто, больший — `-`;
- при наличии лекарственной терапии присутствует `e1101 = 4+` с уточнением
  `препараты`;
- количество мероприятий равно числу датовых ячеек с `+`; `10.55+` считается один
  раз;
- минимум 180 минут проверяется только по активным дням с понедельника по пятницу
  и выдаёт предупреждение, не блокировку;
  суббота и воскресенье в эту проверку не входят;
- любую проблему можно явно проигнорировать для текущего состояния данных; она
  остаётся видимой как информационная строка, а изменение связанного значения
  требует нового подтверждения;
- для МДРК-2 цель выводится как «Достигнута в полном объёме», задачи — как
  «Выполнены в полном объёме»;
- полностью пустые строки удаляются, частично заполненные не исчезают молча.

## Выписной эпикриз

- текущая выписка и первичный профильный осмотр связываются по совпавшему номеру
  медицинской карты либо по полному ФИО вместе с датированной привязкой к эпизоду;
- дополнительные клинические источники принимаются по тому же номеру карты либо
  по датированной точке внутри госпитализации; одной общей папки или одного ФИО
  недостаточно;
- итоговые МКФ, шкалы, цель и выполненная программа берутся только из структурно
  подтверждённого финального МДРК текущего эпизода;
- текстовые блоки проверяются в форме, количество структурных строк показывается
  до генерации, а сами таблицы окончательно проверяются в созданном DOCX;
- блокирующие проблемы нельзя подтвердить вручную; предупреждения требуют явного
  согласия, а исходные документы и runtime-шаблон нельзя перезаписать;
- итоговый DOCX сохраняет шапку и колонтитулы шаблона, проходит санитарную очистку
  и повторное открытие до атомарной публикации.

## Локальная приёмка

Референсные папки и ручные МДРК хранятся только локально и не попадают в репозиторий, сборку или папку поставки. Перед передачей внутреннего пилота нужно проверить минимум одну МДРК-1 и одну МДРК-2. В таблицах DOCX должны повторяться заголовки, критические строки не должны разрываться между страницами, а метаданные исходника не должны переноситься в новый документ.

## Статусы

- `SUCCESS`: сквозной сценарий прошёл, DOCX структурно и визуально проверен.
- `PARTIAL`: программа работает, но Windows EXE или Word COM ещё не проверены на
  целевом Windows-компьютере.
- `BLOCKED`: нет минимальных данных эпизода либо подходящего Windows-окружения для
  обязательной финальной проверки сборки.
