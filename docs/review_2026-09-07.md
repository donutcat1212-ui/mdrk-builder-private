# Ревью бэкенда и интерфейса MDRK Builder

Дата: 07.09.2026. Статус: **PARTIAL** — исправления и локальные проверки завершены; Windows EXE и настольный Word в клинике не проверены.

Объект: текущие исходники версии 1.3.0, базовый HEAD `3567abd5a54d2fe47d66644f97c624c1141b2e7d` и рабочие изменения. Проверены извлечение МКФ, сверка итогового МДРК, происхождение шкал, редактирование таблиц и заключений, переключение документов, повторное сканирование и вывод DOCX. Два независимых ревью охватывали бэкенд и интерфейс; выводы проверялись воспроизводимыми примерами. Это ограниченный аудит указанных сценариев, а не гарантия отсутствия других ошибок.

## Spec — бэкенд и контракты данных

Основания: `AGENTS.md`, `CONTEXT.md`, `docs/acceptance.md`: неизвестные значения остаются пустыми; частично заполненные строки не исчезают; владелец входит в ключ домена; источники соответствуют значениям.

| Приоритет | Подтверждённая ошибка | Исправление и проверка |
|---|---|---|
| P1 | При пустой исходной ячейке повторная оценка МКФ становилась исходной. | Пара сохраняет позиции. Проверены пары `(пусто, 1)`, `(0, 2)`, `(2, пусто)`; изменены `application/extractors.py`, `scanner.py`, `final_mdrk.py`. |
| P1 | Строка с кодом, описанием и двумя пустыми оценками пропадала. | Строка сохраняется; оценки пусты, для неполной пары добавляется предупреждение. |
| P1 | При совпадении кода и описания строка другого специалиста терялась при применении финального МДРК. | Ключ сверки учитывает владельца. Для отсутствующей итоговой точки сохраняется строка с пустой оценкой и предупреждением. Описательный Pf сохраняет особое правило объединения. |
| P2 | Значение шкалы исправлялось по выписке, но ссылка оставалась на ошибочный МДРК. | Скорректированное значение ссылается на выписку, предупреждение — на МДРК. Источник проходит через проекцию строки и защиту от перезаписи. Общая ссылка раздела не назначается при смешанных источниках. |

Тесты: `test_final_mdrk.py`, `test_scanner.py`; существующие тесты извлечения, снимков и выписки. Добавлены проверки исходного файла скорректированной шкалы, отсутствия выдуманного источника и сохранения пропущенных точек.

## Standards — интерфейс и сохранность правок

Основание: согласованность отображаемой строки с редактируемым объектом, сохранение ручных правок при пересканировании, соответствие выбранного документа формируемому снимку.

| Приоритет | Подтверждённая ошибка | Исправление и проверка |
|---|---|---|
| P1 | При переходе от специалиста A к B текст A мог перезаписывать заключение B. | Редактор сохраняет ссылку на фактически показанного специалиста; устаревший объект после удаления/пересканирования не изменяется. `test_specialist_selection.py`. |
| P1 | В МДРК-1 двойной клик по «Ответственному» открывал скрытую повторную оценку. | Сопоставление идёт по отображаемым столбцам, координаты — по идентификатору столбца; F2 выбирает первую видимую редактируемую ячейку. `test_inline_tree.py`. |
| P1 | Пересканирование продолжалось после неуспешной проверки даты, заменяя несохранённую форму. | Отказ применения сохраняет прежнюю форму и текст; идентификационные данные присваиваются только после успешного разбора всех дат. `test_document_panel_rescan.py`. |
| P2 | Вставка текста без KeyRelease могла не считаться ручной правкой и теряться. | Использован сигнал изменения Text; перед применением также сверяются фактические значения. Проверена вставка без клавиатурного события. |
| P2 | После отказа переключения интерфейс обозначал МДРК-2, а генератор оставался на МДРК-1. | При отказе откатываются оба указателя документа. Проверены оба направления и обе причины отказа. `test_document_selection.py`. |

Замечания только о стиле или размере файлов без показанного функционального последствия не включались.

## Читаемость МКФ и источники

- Добавлены границы строк и столбцов в обеих таблицах МКФ через общий `ui/icf_table.py`.
- Для источников конкретной строки используются ПКМ и Shift+F10. Кнопок в ячейках и строках нет; дополнительная кнопка выбранной строки МКФ скрыта. Общая кнопка исходного МДРК-2 в выписке сохранена.
- Сохранены штатные Treeview, редактор на месте, выбор строк, группировка и перетаскивание.
- Оформление использует стандартные элементы темы, без зависимости от нового табличного пакета. Основание реализации: [документация ttk::style](https://www.tcl-lang.org/man/tcl8.6/TkCmd/ttk_style.htm).
- Локальное создание Tk-интерфейса проходит. Визуальная проверка именно сетки в Windows/Tk 8.6 ещё нужна; локальный адаптер снимков не смог адресовать окно Python. Внешний вид не объявляется проверенным по одному анализу кода.

## Оставшееся расхождение требований

**P2 — обход блокирующих замечаний при формировании выписки.** Раздел выписки в `docs/acceptance.md` запрещает обход BLOCKING, тогда как `write_discharge_summary_docx(ignore_issues=True)` и тест `test_writer_requires_explicit_override_for_blocking_issue` намеренно допускают его. Общие правила документа также говорят о возможности игнорировать любую проблему. Поведение не изменено: нужен выбор единого правила, затем синхронизация требований и реализации.
