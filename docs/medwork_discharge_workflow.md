# Выписка отделения из MedWork и документов эпизода

Статус реализации: success для исходного кода и локальной проверки. Windows-сборка не обновлялась.

Рабочий сценарий: сначала врач формирует выписку в МИС, затем кладёт её в папку текущей госпитализации рядом с первичными осмотрами, осмотрами специалистов и листом назначений. Программа собирает документ в формате отделения. Имя файла МИС произвольное: тип определяется по содержимому. DOC преобразуется установленным Word в Windows; локальная проверка выполнена LibreOffice.

Готовая выписка отделения из предоставленного архива использована как образец структуры и оформления. Её индивидуальные клинические назначения не превращаются в общие значения по умолчанию. Эталонный файл не входил во входные данные контрольного формирования.

## Приоритеты источников

| Раздел | Источник |
|---|---|
| Паспортная шапка, адреса, госпитализация, финансирование, ОМС, ВМП | Текущая выписка МИС, после сопоставления эпизода |
| Диагноз | Первичный осмотр невролога; сохраняется весь блок в исходном порядке, включая повторные сопутствующие заболевания |
| Жалобы, анамнез, состояние при поступлении | Первичный осмотр, с сохранением переносов и подразделов анамнеза жизни |
| Представленные обследования | Явный раздел первичного осмотра; также блок выполненных вмешательств, если все распознанные даты предшествуют поступлению |
| Заключения и шкалы специалистов | Их собственные документы и общая модель снимков МДРК; ФТ с динамикой, без копий его строк МКФ из неврологического осмотра |
| Общие таблицы шкал при поступлении/выписке | Врачебные шкалы; шкалы ФТ/нейропсихолога расположены в соответствующих блоках специалистов |
| МКФ | Источники специалистов; колонки находятся по заголовкам, включая 16-колоночную форму и сокращения «Итогбалл» / «Повт.балл» |
| Проведённые реабилитационные процедуры | Датированные отметки «+» листа назначений в пределах госпитализации |
| Лекарственная терапия, трансфузии, операции, дополнительные сведения | Заполненные соответствующие разделы текущей выписки МИС |
| Соматический и неврологический статус при выписке | Раздел состояния при выписке МИС; не подменяется первичным статусом или образцом другого пациента |
| Трудоспособность, рекомендации | Фактический текст МИС при наличии; иначе заполнение врачом |
| Подписи | Подписной блок МИС; технические разделители таблицы не выводятся как символы `|` |

Источники доступны в интерфейсе, включая новую вкладку шапки. Неизвестные клинические данные остаются пустыми. Это уточняет прежнее поведение с шаблонными клиническими значениями: состояние при выписке, рекомендации с лекарствами, трудоспособность, отсутствие операций и улучшение самочувствия больше не утверждаются автоматически при отсутствии источника. Пользовательские типовые выделения в паспортной шапке сохранены.

## Исправления по предоставленным файлам

- Заполненные поля МИС теперь доходят до выписки вместо пустых строк/заготовок.
- Повторные заголовки сопутствующих заболеваний не обрезают диагноз.
- Операции в анамнезе, постоянно принимаемые препараты, эпидемиологический и экспертный анамнез не обрезают анамнез жизни. Физикальное исследование остаётся отдельным разделом.
- МКФ с 16 колонками и сокращёнными заголовками ФТ читается по именам колонок, а не по фиксированным позициям 15-колоночной формы.
- Один день за пределами госпитализации не исключает весь лист назначений. Выполнения в периоде сохраняются; выходящие за него не включаются и сопровождаются замечанием. Полностью посторонний период и явный конфликт пациента по-прежнему исключаются.
- Шкалы ФТ и нейропсихолога не повторяются в общих врачебных таблицах. Встроенный редактор сохраняет доступ ко всем данным и источникам.

## Проверка и границы

Проверка использовала копии локальных исходников. Архив и исходный DOC не изменялись; клинические документы не добавлены в репозиторий. Для регрессии добавлены исключительно синтетические данные: поля МИС, повторные диагнозы, подразделы анамнеза, частичное пересечение дат назначений, формы МКФ с 16 колонками.

В проверяемом примере дата выписки МИС и дата окончательного образца различаются на день. Пользователь уточнил: МИС начали заполнять накануне фактической выписки. Дата МИС служит исходным значением, а не безусловным приоритетом. Врач может исправить дату в поле «Выписка» и повторно считать документы. Повторный сбор пересчитывает период, отбор источников, процедуры и шкалы, обновляет даты шапки и сохраняет ручные текстовые правки. Сохранение после изменения периода до повторного сбора блокируется, чтобы не выгрузить устаревшие расчёты. Исходные документы остаются неизменными.

В исходной выгрузке нет заполненной лекарственной терапии и окончательных рекомендаций, которые есть в готовом образце. Не все итоговые врачебные шкалы и клинические уточнения готового образца присутствуют в исходниках. Контрольное формирование поэтому является черновиком для сверки, а не заменой окончательного врачебного эпикриза. Отсутствующие повторные значения не заполняются исходными ради визуального совпадения с образцом.

Итоговая проверка: 357 тестов passed; compileall, privacy gate и git diff --check пройдены. Контрольный DOCX повторно открыт, проверена целостность ZIP и все 10 страниц рендера LibreOffice. После удаления технического разделителя повторный рендер страниц 1–9 побайтно совпал с просмотренным; изменённая страница 10 просмотрена повторно. Windows/Word COM в этой проверке не запускались.

Проверка исправления даты: подтверждённая дата повторно применена к локальному примеру; выполнения последнего дня восстановлены. Синтетические регрессии покрывают передачу даты из интерфейса в фоновый сбор, сохранение ручного текста и запрет экспорта без пересчёта.
