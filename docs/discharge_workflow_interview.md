# Согласованный процесс подготовки документов

Статус: согласовано. Пользователь подтвердил рекомендуемые решения интервью,
дополнил требования и поручил разработку с публикацией Windows Internal Use.

## Последовательность

Первичные осмотры основного врача и специалистов → МДРК-1 → дневники → МДРК-2
и выписной эпикриз в любом удобном врачу порядке. Выгрузка МИС содержит сведения,
но результат оформляется по шаблону отделения. Готовый МДРК-2 не является условием
подготовки выписки; собственные выходные DOCX не становятся источниками фактов.

Проект выписки собирается и без текущей МИС. Доступные данные текущего эпизода
сохраняются, отсутствующие поля видны врачу. Предшествующая выписка другого
отделения не заполняет текущую шапку, состояние, рекомендации или подписи.
Совпадение пациента само по себе не означает совпадение госпитализации.

## Решения интервью

| Вопрос | Принятое решение |
|---|---|
| Источник первичных сведений | Текущий первичный осмотр основного врача: диагноз, жалобы, анамнез, статус при поступлении |
| Текущая МИС ещё не выгружена | Собрать доступный проект; не подставлять прежнюю госпитализацию |
| Итоговое состояние | Последний доступный осмотр основного врача внутри текущего периода, включая обычный дневник; сохранить источник и дату, не дописывать улучшение |
| Исследования | До поступления — представленные документы; во время госпитализации — лабораторные и инструментальные исследования |
| Потенциал | По умолчанию «средний» |
| Результат цели выписки | По умолчанию «достигнут в полном объёме» |
| Приоритет значений | Ручная правка → явное итоговое сведение текущего эпизода → согласованное типовое значение |
| Общие итоговые рекомендации отсутствуют | Поле для врача; индивидуальные назначения из готового образца не являются общим шаблоном |
| Подписи текущей МИС отсутствуют | Лечащий врач из текущего первичного осмотра; заведующий из настройки отделения; отдельные редактируемые поля |
| Редактирование | В главном окне и ячейках таблиц; без отдельных окон при двойном щелчке |
| Рабочий черновик | Локальный каталог пользователя, без служебного JSON в папке пациента |

## Дополнения для МДРК и специалистов

- Диагноз МДРК-1 переносится полностью из первички: основное заболевание,
  сопутствующие заболевания, дополнительные сведения и ШРМ.
- Плановая длительность МДРК-1 — 16 койко-дней с ручной правкой; она хранится
  отдельно от фактической длительности курса.
- Кратность процедуры должна быть доступна. Явный план приоритетнее расчёта
  по выполненным занятиям; использование расчётной кратности в МДРК-1 отмечается
  для проверки. Выполненное количество не объявляется назначенным количеством.
- Задачи логопеда и патопсихолога из пункта 11 переносятся в задачи реабилитации.
  Формулировка «краткосрочная цель» в этот раздел не включается.
- Нейропсихологическое заключение сохраняет полный абзац об отсутствии оснований
  для продолжения работы и полную рекомендацию с кодом, названием и хвостом
  процедуры в скобках.
- У логопеда сохраняются пункты после «На основании данных … рекомендовано».
  Индивидуальная программа остаётся отдельным пунктом до детализации
  «преодоление / восстановление».
- Заключение невролога при отсутствии явного текста:
  «показано проведение курса реабилитационного лечения».
- МКФ эрготерапевта проходит тот же профильный отбор, что и другие специалисты.
  Ручное добавление пустой строки должно сразу показывать её и открывать ячейку.
- Заключение и история его правок принадлежат конкретному специалисту и осмотру.
  Правка невролога в МДРК-2 не должна появляться у остальных специалистов;
  это же правило проверяется в МДРК-1 и выписке.

## Проверка результата

Регрессии покрывают несовместимую прошлую выписку вместе с текущей первичкой,
проект без МИС, паспортные поля подтверждённой МИС, дневниковое состояние,
даты исследований, полноту диагнозов и заключений, задачи специалистов,
редактирование МКФ/программы/подписей и независимость плановых койко-дней.

Контроль на локальных источниках выполняется отдельно от синтетических тестов.
Исходники неизменны, клинические документы и результаты их рендера не входят
в Git или Windows ZIP. Сверяется именно созданный DOCX и каждая его страница.
Приёмка Word COM на целевом Windows-компьютере остаётся отдельной границей
Internal Use, которую сборка и UI smoke в Windows CI не подтверждают.
