# MDRK Builder

Локальная Windows-программа для подготовки редактируемых МДРК-1 и МДРК-2 из папки одного эпизода стационарной реабилитации.

Программа сканирует DOCX/DOC/RTF, собирает основные клинические разделы, заключения специалистов, шкалы, домены МКФ и фактически выполненные процедуры из листа назначений. Перед сохранением все ключевые поля можно проверить и изменить в простом Tkinter-интерфейсе.

## Граница приватности

- Работа выполняется локально и офлайн: в программе нет сетевых запросов, облачного OCR, API или телеметрии.
- Исходные документы открываются только для чтения и не изменяются.
- DOC и RTF на рабочем Windows-компьютере преобразуются во временный DOCX через установленный Microsoft Word; временные файлы удаляются после сканирования.
- Сформированный DOCX — редактируемый черновик. Его необходимо проверить до использования как медицинского документа.
- PDF и сканы в MVP не читаются. Они остаются видимым ограничением, а не «успешно извлечёнными» данными.

Не запускайте массовую обработку, пока на небольшой анонимизированной выборке не сверены все поля, таблицы и форматирование.

## Требования

Рабочая Windows-установка:

- Windows 10/11 x64;
- Python 3.12 (предпочтительно) или 3.11 для запуска из исходников/сборки;
- настольный Microsoft Word для чтения legacy DOC/RTF;
- доступ к папке эпизода и месту сохранения результата.

Для разработки на macOS/Linux DOC/RTF можно преобразовывать через LibreOffice. Производственный Windows-маршрут рассчитан на Microsoft Word.

Python нужен только для запуска из исходников и сборки. Готовый `MDRK_Builder.exe` не требует отдельной установки Python. Первая сборка из исходников может потребовать интернет для загрузки зависимостей; сама работа с документами остаётся офлайн.

## Установка готовой Windows-версии

Публичные сборки доступны в разделе **Releases** этого репозитория; для
скачивания регистрация на GitHub не нужна. Самый простой вариант — скачать
`MDRK_Builder-v0.1.6.exe`, положить его в
обычную пользовательскую папку и запустить. Это полностью переносимая версия:
другие DLL, Python и права администратора не нужны. ZIP содержит тот же EXE
вместе с README и сведениями о сборке. Альтернативный архив называется
`MDRK_Builder-v0.1.6-windows-x64.zip`; скачивать оба варианта не требуется.

Перед первым запуском сравните SHA-256 файла с `SHA256SUMS.txt` из того же
релиза. EXE пока не подписан цифровым сертификатом, поэтому Windows SmartScreen
может показать предупреждение `Unknown publisher`.

Релиз `v0.1.6` является **release candidate** до отдельной приёмки конвертации
DOC/RTF на Windows-компьютере с установленным настольным Microsoft Word.

## Быстрый запуск из исходников

С `uv`:

```powershell
uv sync --extra dev
uv run mdrk-builder
```

Или через обычный `venv`:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\activate
python -m pip install -e ".[dev]"
mdrk-builder
```

Основной сценарий UI:

1. Нажать **«Обзор…»** и выбрать папку реабилитационного эпизода.
2. Нажать **«Сканировать»** и дождаться завершения Word-конвертации.
3. Выбрать **МДРК-1** или **МДРК-2**.
4. Проверить список источников, основные поля, МКФ, шкалы, процедуры, заключения и вкладку предупреждений.
5. Заполнить пропуски или исправить значения вручную.
6. Нажать **«Создать DOCX…»**, затем открыть результат в Word и выполнить финальную сверку.

Дата заседания МДРК-1 рассчитывается автоматически на 08:00:

- поступление с понедельника по четверг — на следующий день;
- в пятницу — на понедельник;
- в субботу или воскресенье — на вторник.

Реабилитационный потенциал по умолчанию заполняется как **«средний»**. Кратность
процедур выводится из дат с «+»: **ежедневно**, **через день**, **1–3 раза в неделю**,
**однократно**, а при нерегулярном графике — **периодически**.

На каждый активный будний день, где есть хотя бы один «+», программа суммирует минуты.
Суббота и воскресенье в правило 180 минут не входят. Если в будний день получается
меньше 180 минут, программа показывает блокировку, которую можно явно проигнорировать.

Любую строку на вкладке **«Предупреждения»** можно выделить и явно проигнорировать.
Она останется видимой как информационная отметка. Игнорирование относится только к
текущему состоянию данных и сбрасывается после нового сканирования или изменения
связанного значения.

В полях ввода работают `Ctrl+C`, `Ctrl+V`, `Ctrl+X` и `Ctrl+A`, в том числе при русской раскладке.
В таблицах МКФ, шкал, процедур и заключений выделенные строки удаляются клавишей `Delete`.

Персональный фактор `Pf` объединяется в одну описательную строку по всему эпизоду:
психологический источник имеет приоритет, затем используются ФРМ/невролог и другие
профильные специалисты. Числовой квалификатор для `Pf` не требуется.

Документ с явно другим номером ИБ отмечается серым на вкладке **«Источники»** и не
участвует в сборке дат, диагноза и исследований. Если сканер всё равно нашёл конфликт номера ИБ
или даты поступления, сначала проверьте значение в **«Основное»**. Если значение уже верное,
выделите строку в **«Предупреждения»** и нажмите **«Игнорировать выбранное…»**.
Если вы изменили номер ИБ или дату поступления, сначала повторно нажмите **«Сканировать»**:
программа заново выберет источники и пересчитает границы эпизода. После сканирования выделите
оставшийся конфликт и при необходимости проигнорируйте его. Решение привязано к текущему
состоянию данных; после новой правки блокировка вернётся.

Если вы исправили дату или время заседания, повторно нажмите
**«Сканировать»**. Программа заново отберёт диагноз, заключения, шкалы и МКФ
не позже новой границы. До повторного сканирования генерация блокируется.
Если первый врачебный осмотр датирован позже автоматически рассчитанного МДРК-1,
его поля показываются только как предварительный просмотр, а генерация остаётся
заблокированной до проверки времени заседания и повторного сканирования.

Красные проблемы блокируют генерацию. Жёлтые допускают создание редактируемого DOCX только после явного подтверждения пользователя.

## CLI

Только сканирование и сводка:

```powershell
mdrk-scan "C:\Patients\Episode-719"
```

Итоговый снимок с ручным временем заседания и созданием DOCX:

```powershell
mdrk-scan "C:\Patients\Episode-719" `
  --kind final `
  --meeting "19.06.2026 09:30" `
  --output "C:\Patients\Episode-719\МДРК_2.docx"
```

Машиночитаемая локальная сводка:

```powershell
mdrk-scan "C:\Patients\Episode-719" --json
```

Если `--output` уже существует, CLI откажется его заменять. Осознанная замена включается флагом `--force`. В UI то же решение подтверждается стандартным диалогом Windows.

Коды завершения: `0` — можно продолжать/документ создан; `2` — остались блокирующие поля; `1` — системная ошибка.

## Сборка EXE на Windows

Сборка выполняется **на Windows**, кросс-сборка с macOS не поддерживается:

```bat
build_windows.bat
```

Скрипт выбирает Python 3.12 или 3.11, создаёт `.venv-win`, ставит зависимости проекта, запускает compile/test, проверяет Tkinter и pywin32, собирает one-file EXE через `mdrk_builder.spec` и в `--smoke-test-ui` проверяет наличие шаблона, генерацию минимального DOCX и запуск UI. Ожидаемый файл:

```text
dist\MDRK_Builder.exe
```

Для ручной сборки на Windows переносится весь исходный каталог проекта или распакованный `mdrk_builder-0.1.6.tar.gz`. Каталоги `.venv`, `.venv-win`, `build` и `dist` переносить не нужно. Wheel — это пакет для Python-установки и smoke-проверки, а не готовый Windows EXE.

### Честный статус сборки

GitHub Actions собирает EXE на Windows x64 и перед публикацией запускает тесты,
проверяет Windows-импорты, встроенный шаблон, создание минимального DOCX и
реальную инициализацию Tkinter UI. **COM-конвертация реальных DOC/RTF через Word и
визуальная проверка результата на целевом Windows-компьютере пока не
подтверждены.** До такой проверки EXE нельзя считать готовым к клиническому
использованию.

Минимальная Windows-приёмка:

1. Запустить `build_windows.bat` без ошибок.
2. Открыть EXE без Python в `PATH`.
3. На копии анонимизированной папки проверить DOCX, DOC и RTF.
4. Сверить МДРК-1 и МДРК-2 построчно с ручными эталонами.
5. Убедиться, что после сканирования не остаётся `WINWORD.EXE`.
6. Проверить документ в установленной версии Word и только затем переносить EXE на рабочий компьютер.

## Известные границы MVP

- Не исправляет неверные клинические даты, опечатки и противоречия автоматически.
- Не сочиняет диагноз, заключение или динамику.
- Не интерпретирует направление улучшения произвольных шкал.
- Не угадывает неизвестного исполнителя; без дат с «+» кратность нельзя вывести надёжно.
- Проверка 180 минут зависит от корректно извлечённых дат «+» и длительности процедур; неполные данные требуют ручной сверки.
- При отсутствии повторной оценки МКФ оставляет пропуск и предупреждение.
- Источник с явно другим номером ИБ не используется в сборке; пограничные конфликты всё равно требуют ручной проверки.

Архитектурные термины и инварианты находятся в [CONTEXT.md](CONTEXT.md), решения по эпизоду и Windows runtime — в `docs/adr/`.
