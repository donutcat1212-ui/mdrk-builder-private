# MDRK Builder Internal 1.2.0

Локальный необязательный Windows-инструмент для подготовки редактируемых проектов МДРК-1, МДРК-2, выписного эпикриза и оборотного листа из папки одного эпизода стационарной реабилитации.

Программа сканирует DOCX/DOC/RTF, собирает основные клинические разделы, заключения специалистов, шкалы, домены МКФ и фактически выполненные процедуры из листа назначений. Перед сохранением все ключевые поля можно проверить и изменить в простом Tkinter-интерфейсе.

Программа не выполняет диагностику, не назначает лечение и не заменяет профессиональное решение специалиста. Результат может содержать пропуски или ошибки распознавания и должен быть проверен до подписания и включения в медицинскую документацию. Программное обеспечение предоставляется «как есть», без гарантии безошибочного формирования.

## Граница приватности

- Работа выполняется локально и офлайн: в программе нет сетевых запросов, облачного OCR, API или телеметрии.
- Исходные документы открываются только для чтения и не изменяются.
- DOC и RTF на рабочем Windows-компьютере преобразуются во временный DOCX через установленный Microsoft Word; временные файлы удаляются после сканирования.
- Сформированный DOCX остаётся обычным редактируемым Word-документом без водяных знаков.
- PDF и сканы в MVP не читаются. Они остаются видимым ограничением, а не «успешно извлечёнными» данными.

Версия 1.2.0 предназначена для ограниченного внутреннего пилота. Не выносите папку поставки, `issues.txt` и внутренние шаблоны за пределы защищённой сети отделения.

## Требования

Рабочая Windows-установка:

- Windows 10/11 x64;
- Python 3.12 (предпочтительно) или 3.11 для запуска из исходников/сборки;
- настольный Microsoft Word для чтения legacy DOC/RTF;
- доступ к папке эпизода и месту сохранения результата.

Для разработки на macOS/Linux DOC/RTF можно преобразовывать через LibreOffice. Производственный Windows-маршрут рассчитан на Microsoft Word.

Python нужен только для запуска из исходников и сборки. Готовый `MDRK_Builder.exe` не требует отдельной установки Python. Первая сборка из исходников может потребовать интернет для загрузки зависимостей; сама работа с документами остаётся офлайн.

## Установка готовой Windows-версии

Готовая поставка — папка `MDRK_Builder_1.2.0_Internal`. Скопируйте её целиком в защищённую сетевую папку отделения. Внутри:

- `MDRK_Builder.exe` — готовая переносимая программа;
- `issues.txt` — общий файл обратной связи;
- `README_ПЕРЕД_ИСПОЛЬЗОВАНИЕМ.txt` — краткая инструкция и условия.

Программа не требует установки, Python или прав администратора. У пользователей должно быть право записи в сетевую папку, чтобы форма обратной связи могла дописывать `issues.txt`.

EXE пока не подписан цифровым сертификатом, поэтому Windows SmartScreen
может показать предупреждение `Unknown publisher`.

Версия `1.2.0` является внутренним пилотом. Перед расширением круга пользователей нужна отдельная приёмка конвертации
DOC/RTF на Windows-компьютере с установленным настольным Microsoft Word.
Word не требуется назначать программой по умолчанию: служебный экземпляр отключает
этот запрос, не меняя файловые ассоциации Windows. Ошибка закрытия Word после
успешного сохранения не отменяет сканирование; при зависании завершается только
созданный программой служебный процесс Word. Макросы принудительно отключаются до
открытия каждого legacy DOC/RTF в этом процессе.

## Быстрый запуск из исходников

С `uv`:

```powershell
uv sync --extra dev
uv run mdrk-builder
```

Или через обычный `venv`:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\activate
python -m pip install -e ".[dev]"
mdrk-builder
```

Основной сценарий UI:

1. Нажать **«Обзор…»** и выбрать папку реабилитационного эпизода.
2. Нажать **«Сканировать»** и дождаться завершения Word-конвертации.
3. Выбрать **МДРК-1** или **МДРК-2**.
4. Проверить список источников, основные поля, МКФ, шкалы, процедуры, заключения и вкладку предупреждений.
5. Заполнить пропуски или исправить значения вручную.
6. Нажать **«Создать DOCX…»**, затем открыть результат в Word и выполнить финальную сверку.
7. Для отзыва открыть **«Справка → Обратная связь…»**. Программа запишет в `issues.txt` только то, что ввёл пользователь; данные пациента, пути и логи автоматически не прикладываются.

Выписной эпикриз создаётся отдельной кнопкой **«Выписной эпикриз…»**. Перед
сохранением открывается самостоятельная прокручиваемая форма: перенесённые и
шаблонные текстовые блоки можно проверить и изменить, а строка состояния показывает
количество перенесённых доменов МКФ, шкал и процедур. Эти структурные таблицы
окончательно проверяются и при необходимости редактируются в созданном DOCX.
Лекарственные препараты и трансфузии намеренно остаются пустыми для ручного
заполнения. Дополнительные сведения, состояние при выписке, трудоспособность и
рекомендации открываются с текстом утверждённого шаблона.

Источники полей выписного эпикриза разделены явно:

- паспортная шапка, исследования текущей госпитализации, консультации узких
  специалистов и лучевая нагрузка — из выписного эпикриза с тем же номером карты;
- заключительный диагноз, жалобы, анамнезы, статус при поступлении, диета,
  факторы риска и ограничения — из первичного осмотра лечащего врача в папке
  неврологии;
- МКФ, итоговые шкалы и выполненная программа — из структурно распознанного
  МДРК-2 и модели итогового снимка. Имя файла само по себе не делает документ
  итоговым МДРК-2.

Документ другой госпитализации не используется даже при совпадении пациента.
Консультации с датой вне выбранного периода исключаются с предупреждением.
Невозможное значение шкалы не принимается молча: программа показывает причину;
замена допускается только при наличии однозначного подтверждения в текущем
выписном эпикризе и также остаётся видимой для проверки.

Оборотный лист назначений создаётся отдельной кнопкой **«Оборотный лист…»** после
выбора папки эпизода. Его шапка читается только из первичной консультации невролога.
В таблицу попадают отдельные документы консультаций и консилиумов МДРК; УЗИ, ФГДС
и другие исследования автоматически не добавляются. Неподтверждённые даты остаются
пустыми. Между хронологическими блоками оставляются пустые строки для ручного
дозаполнения процедур из МИС. Если в папке уже есть оборотный лист, из него могут быть
перенесены только даты строк МДРК с явной отметкой о необходимости проверки; остальные
вмешательства из старого листа не копируются. Строки можно проверить, исправить,
добавить или удалить перед сохранением DOCX.

Дата заседания МДРК-1 рассчитывается автоматически на 08:00:

- поступление с понедельника по четверг — на следующий день;
- в пятницу — на понедельник;
- в субботу или воскресенье — на вторник.

Реабилитационный потенциал по умолчанию заполняется как **«средний»**. Кратность
процедур выводится из дат с «+»: **ежедневно**, **через день**, **1–3 раза в неделю**,
**однократно**, а при нерегулярном графике — **периодически**.

Для МДРК-1 этапная цель и реабилитационные задачи читаются не только из врачебного
осмотра, но и из явных разделов профильных первичных консультаций. Короткосрочные
задачи последних содержательных документов каждого специалиста объединяются без
дублирования; рекомендации и назначения после раздела задач не подмешиваются.

Для МДРК-2 диагноз, анамнезы, лабораторные и инструментальные исследования
начинаются с первичного либо первого содержательного текста. Поздние содержательные
изменения добавляются с датой и временем; служебные фразы «без изменений»,
«без дополнений» и «по ИПМР» пропускаются. Скопированные исследования
дедуплицируются, но новые фрагменты и изменившиеся числовые результаты сохраняются.

МКФ и шкалы в МДРК-2 сводятся к двум точкам: первой валидной и последней валидной
не позже заседания. Промежуточные копии не выводятся; новый домен или новая шкала,
возникшие во время курса, используют первую дату появления как исходную точку.
Если повторной оценки МКФ нет, в редактируемом МДРК-2 исходный квалификатор
дублируется во второй столбец. Для врача ФРМ/невролога исходное значение шкалы при
отсутствии повторного также дублируется, а дата повторного осмотра и столбца шкал
приравнивается к дате заседания МДРК-2. Источник при этом не изменяется и отдельная
клиническая динамика не выдумывается. В МДРК-1 повторная оценка и динамика скрыты.
Заключение выводится только последнее содержательное для каждого специалиста.

На каждый активный будний день, где есть хотя бы один «+», программа суммирует минуты.
Суббота и воскресенье в правило 180 минут не входят. Если в будний день получается
меньше 180 минут, программа показывает предупреждение, но не блокирует создание DOCX.

Любую строку на вкладке **«Предупреждения»** можно выделить и явно проигнорировать.
Она останется видимой как информационная отметка. Игнорирование относится только к
текущему состоянию данных и сбрасывается после нового сканирования или изменения
связанного значения.

В полях ввода работают `Ctrl+C`, `Ctrl+V`, `Ctrl+X` и `Ctrl+A`, в том числе при русской раскладке.
По правой кнопке мыши доступно обычное меню «Вырезать / Копировать / Вставить /
Выделить всё»; в многострочных полях также доступны отмена и повтор.
В таблицах МКФ, шкал, процедур и заключений выделенные строки удаляются клавишей `Delete`.

Персональный фактор `Pf` объединяется в одну описательную строку по всему эпизоду:
психологический источник имеет приоритет, затем используются ФРМ/невролог и другие
профильные специалисты. Числовой квалификатор для `Pf` не требуется.
Поле ответственного специалиста у домена можно оставить пустым. Из таблицы ШРМ в
первичной консультации невролога переносятся только функции и структуры (`b`, `s`),
лекарственные препараты (`e1101`) и персональные факторы (`Pf`). Скопированные в неё
домены физической терапии и физической реабилитации не переносятся в МДРК.

В конце документа всегда создаётся единая таблица полного состава МДРК: врач ФРМ,
специалист по физической реабилитации, нейропсихолог, патопсихолог, медицинский
логопед, специалист по эргореабилитации, консультанты и заведующий отделением.
ФИО автоматически берётся из последнего доступного профильного документа не позже
заседания, включая первички и дневники без итогового заключения. Заведующий
отделением всегда указывается как **Поляев Б.Б.** Если ФИО другого специалиста не
найдено, соответствующая ячейка остаётся пустой для ручного заполнения. В МДРК-2
раздел 12 называется **«Выполненная программа медицинской реабилитации»**.

Документ с явно другим номером ИБ отмечается серым на вкладке **«Источники»** и не
участвует в сборке дат, диагноза и исследований. Если сканер всё равно нашёл конфликт номера ИБ
или даты поступления, сначала проверьте значение в **«Основное»**. Если значение уже верное,
выделите строку в **«Предупреждения»** и нажмите **«Игнорировать выбранное…»**.
Если вы изменили номер ИБ или дату поступления, сначала повторно нажмите **«Сканировать»**:
программа заново выберет источники и пересчитает границы эпизода. После сканирования выделите
оставшийся конфликт и при необходимости проигнорируйте его. Решение привязано к текущему
состоянию данных; после новой правки блокировка вернётся.

Если вы исправили дату или время заседания, повторно нажмите
**«Сканировать»**. Программа заново отберёт диагноз, заключения, шкалы и МКФ
не позже новой границы. До повторного сканирования генерация блокируется.
Если первый врачебный осмотр датирован позже автоматически рассчитанного МДРК-1,
его поля показываются только как предварительный просмотр, а генерация остаётся
заблокированной до проверки времени заседания и повторного сканирования.

Красные проблемы блокируют генерацию. Жёлтые предупреждения не блокируют DOCX; любую строку можно осознанно перевести в информационную отметку.

## CLI

Только сканирование и сводка:

```powershell
mdrk-scan "C:\Work\Episode"
```

Итоговый снимок с ручным временем заседания и созданием DOCX:

```powershell
mdrk-scan "C:\Work\Episode" `
  --kind final `
  --meeting "19.06.2026 09:30" `
  --output "C:\Work\Episode\МДРК_2.docx"
```

Машиночитаемая локальная сводка:

```powershell
mdrk-scan "C:\Work\Episode" --json
```

Если `--output` уже существует, CLI откажется его заменять. Осознанная замена включается флагом `--force`. В UI то же решение подтверждается стандартным диалогом Windows.

Коды завершения: `0` — можно продолжать/документ создан; `2` — остались блокирующие поля; `1` — системная ошибка.

## Сборка EXE на Windows

Сборка выполняется **на Windows**, кросс-сборка с macOS не поддерживается:

```bat
build_windows.bat
```

Скрипт выбирает Python 3.12 или 3.11, создаёт `.venv-win`, ставит зависимости проекта, запускает compile/test, проверяет Tkinter и pywin32, собирает one-file EXE через `mdrk_builder.spec`, выполняет `--smoke-test-ui` и создаёт готовую внутреннюю папку:

```text
dist\MDRK_Builder_1.2.0_Internal\
```

В папку поставки не включаются исходники, тесты, логи, корпус документов и сведения о сборочном окружении.

### Честный статус сборки

Закрытая Windows-сборка запускает тесты,
проверяет Windows-импорты, оба встроенных шаблона, создание и повторное открытие
минимальных МДРК и выписного эпикриза, а также
реальную инициализацию Tkinter UI. **COM-конвертация реальных DOC/RTF через Word и
визуальная проверка результата на целевом Windows-компьютере пока не
подтверждены.** До такой проверки EXE нельзя считать готовым к клиническому
использованию.

Минимальная Windows-приёмка:

1. Запустить `build_windows.bat` без ошибок.
2. Открыть EXE без Python в `PATH`.
3. На локальной контрольной папке проверить DOCX, DOC и RTF.
4. Сверить МДРК-1 и МДРК-2 построчно с ручными эталонами.
5. Убедиться, что после сканирования не остаётся `WINWORD.EXE`.
6. Проверить документ в установленной версии Word и только затем переносить EXE на рабочий компьютер.

## Известные границы MVP

- Не исправляет неверные клинические даты, опечатки и противоречия автоматически.
- Выписной эпикриз остаётся проектом: ручные блоки, подписи и все предупреждения
  требуют проверки в Word перед включением в медицинскую документацию.
- Не сочиняет диагноз, заключение или динамику.
- Не интерпретирует направление улучшения произвольных шкал.
- Не угадывает неизвестного исполнителя; без дат с «+» кратность нельзя вывести надёжно.
- Проверка 180 минут зависит от корректно извлечённых дат «+» и длительности процедур; неполные данные требуют ручной сверки.
- При отсутствии отдельной повторной оценки МКФ сохраняет исходное значение как
  источник, но в МДРК-2 дублирует его во второй столбец для последующего редактирования.
- Если профильная первичка не содержит исходной точки МКФ или шкалы, программа
  может восстановить её из однозначно распознанного прежнего МДРК-1. Клинический
  текст и заключения из старого МДРК при этом не копируются; МДРК-2 источником не служит.
- Источник с явно другим номером ИБ не используется в сборке; пограничные конфликты всё равно требуют ручной проверки.

Архитектурные термины и инварианты находятся в [CONTEXT.md](CONTEXT.md), решения по эпизоду и Windows runtime — в `docs/adr/`.
